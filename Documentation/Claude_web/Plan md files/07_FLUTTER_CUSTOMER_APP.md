# FLUTTER DEVELOPMENT RULES
## Key Principles
## Clean Architecture Layers
## Project Structure (feature-first)
## Naming Conventions
## BLoC Pattern (Event / State / Bloc)
## Dependency Injection (get_it + injectable)
## Network Layer (Dio + interceptors)
## Error Handling (Either<Failure, T>)
## Navigation (go_router)
## Models & Entities (freezed + json_serializable)
## Forms & Validation
## Testing
## Key Commands
## Dependencies (pubspec.yaml)
Rules to include:

One feature folder = one complete vertical slice (data / domain / presentation)
Domain layer has zero Flutter/Dio dependencies — pure Dart
Repository pattern: abstract in domain, impl in data
BLoC for all screen state; no setState in production pages
Equatable on all Event and State classes
Either<Failure, T> return type on all repository methods and use cases
get_it for DI; register in injection_container.dart
Dio with AuthInterceptor (attaches Bearer token), RetryInterceptor (on 401 → refresh)
flutter_secure_storage for tokens (not SharedPreferences)
go_router with redirect guards for auth; named routes only
freezed for immutable models, entities, states
json_serializable for all API models
CachedNetworkImage for all remote images
Snake_case JSON keys map to camelCase Dart fields via @JsonKey(name:)
No business logic in widgets; widgets only dispatch events and render state
File naming: snake_case.dart; Class naming: PascalCase

API calls:

POST /auth/register → { email, password, firstName, lastName, role: 'CUSTOMER' }
POST /auth/verify-otp → { userId, code }
POST /auth/login → { email, password } → { accessToken, refreshToken, user }
POST /auth/refresh → { refreshToken }
POST /auth/logout (authenticated)
Token storage: flutter_secure_storage keys: access_token, refresh_token, user_json

Splash logic:

Check flutter_secure_storage for token
If token exists → push to home
Else → push to login
